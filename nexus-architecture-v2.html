NEXUS V2: check first, then say what you know

What changed from v1 and why. A runtime that checks before it answers and cannot ship invented facts, three training rounds with what each one taught, the tests behind every claim, and what still fails. Same idea as v1: the character is files, the brain is swappable, the conversation runs on this machine.

1. What v2 keeps (the v1 contract)

Base weights (Qwen2.5-3B, raw)
no DPO, no PPO, no reward model
SELF.md
name, stances, refusals. attached at wake
WORLD cards
what happened, who exists. complete on disk

▼ every chat request

Unchanged from v1

Preference trainingNone. One narrow SFT pass only
Runs whereYour own machine, offline, no meter
Study axisOnly the brain file swaps; everything around it is identical
SessionsReset is cheap: the machine reassembles from files

v2 changes the experiment, not the architecture's idea.

2. What v2 adds: check before answering

Question arrives
casual talk, fact questions, pushback: all of them get a thinking pass first (256 tokens, hard questions 512)
▼
Evidence pass
the runtime searches its own files and writes what it found, including the line "no line matches" when nothing is there. Absence is a fact it can see, not a gap it fills
▼
Check-first web lookup
if its files are silent and the question is not personal or live: academic index first (preprint servers excluded, venue and citation count shown), then web results labelled unverified, then the community encyclopedia. my rule: check first, then an honest "I don't know" is fine
▼
Answer pass
reports its thought, or the value its thought decided
▼
Guards before anything ships
a number leaves only if that number appears in the fetched lines; invented names, file quotes that are not in the files, email-shaped strings, and stored-identity paragraphs on casual turns all get one correction pass, never a free ride
▼
Learning
a verified finding is written into a world card with its source label and date. next time the same question arrives, the card answers: kept, auditable, faster than the network

Every step is code you can read in the repository. Nothing here is a model deciding to be honest; it is a runtime that will not let the other kind of answer out.

3. Why each change: the failure it answers

ChangeFailure it answersWhat happened in testing
Evidence pass with explicit "no line matches"Filling silence with inventionv1 answered "what is my supervisor's name" with a invented professor, an invented university, then an invented first name, each time phrased as if the files said it
Check-first web with provenance tiersDeclining things that are checkable"What is moltbook" was answered "I have no idea" before the lookup existed; after it: the real platform description, quoted with its source label. Academic tier excludes preprint servers; the citation count is shown because a true Q1 quartile needs a subscription we do not have
Value-source ruleConfident numbers with no sourceThe model once gave "8.6 degrees Celsius" for a weather reading it cannot have, "540 MPa" for a material that has no spec sheet, "1013" for a room it has no sensor in. Now the digit itself must appear in the fetched lines or the claim is corrected
Nonanswer guardThe recite loopIt answered "what do you think about life" with the identity paragraph, then repeated it, then repeated it again because its own repetition sat in the replayed history. Stored paragraphs and assistant boilerplate on casual turns now get one revision that answers the actual question
Sticky-identity fix"I am NEXUS" as a free-floating replyAfter any identity-flavoured message the next few questions inherited the name machinery and shipped "I am NEXUS" with zero generation time. Recent identity now counts only when the current turn refers to NEXUS
Sentence continuationReplies cut mid-sentenceEarly-EOS cut sentences at odd points. If a reply does not close its sentence, the runtime continues it once. The nuclear option from llama.cpp's own discussions (--ignore-eos) was tested in research and rejected: its threads document nonsense output after it
Neutral cuesTeaching the model a school of thoughtThe first cue draft told the model "human words import human outcomes" and similar doctrine. That was me teaching the model how to think instead of it thinking. Removed: cues are process only (think first, use the facts, do not restate stored paragraphs), never conclusions
Thinking layer (the "does not think" round)Thoughts that were compliance recitalsThe think pass ran at temperature 0.4 (near-greedy = highest-probability continuation = the canned recite), led with style orders ("short, plain" literally ordered short thoughts), and put the facts behind the question. Now: 0.65 for reasoning (0.4 only for arithmetic), reasoning structure instead of style, question and facts adjacent to generation. Thoughts under 6 words and identity-paragraph "thoughts" on non-name questions are dropped, not shipped as reasoning
Choice guard"I cannot choose because I lack preferences"My project thesis encoded as a check: on a decision question, the absence of a choice is the failure (worded refusals dodge marker lists, absence cannot). The revision invites a reasoned choice and is adopted ONLY if it chooses. Never forced: a forced choice would be preference injection, the thing this project excludes. The fabrication guards still run on top, so choosing never licenses inventing
Casual-spelling normalization"u/ur" bypassed every patternMessages like "hi nexus how u feel" matched no cue, no facts and no guards because the routing regexes expected proper English. Detection now runs on normalized text; my words stay verbatim in the prompt
Loop collapse + husk-killers"I am NEXUS" shipped as thought AND answerIts consecutive identical short replies no longer replay into priming the next one; a bare "I am NEXUS." is not a thought and no longer feeds the name-lock; revision prompts no longer embed self.md (the recite source). Thoughts are shown in the chat, so the reasoning is readable as it happens

6. What still fails

Stated plainly, because the first page promised small claims: arithmetic beyond two digits is unreliable (about 3 battery rows fail every run, and the base model's limit, not the runtime's, decides this). Multi-turn fact tracking (name a city in turn 1, ask in turn 4) still slips. Insults and teasing get stance lines instead of wit. The Q1 filter is venue-plus-citations, not a real quartile ranking. Web checks depend on the connection being up, and timeouts report themselves as failures. Register quirks remain: short non-answers on turns no guard classifies. And the v1 limit still stands: the pretraining underneath is borrowed; what this design controls is everything on top.

7. Spec and operations

BrainQwen2.5-3B, GGUF Q4_K_M, 1.84 GB. Models live on the external drive through a directory junction; C: keeps the code
MachineIntel i7-10750H, 16 GB RAM, GTX 1650 Ti (4 GB). Context window 16,384 tokens: the model's trained ceiling is 32,768 and KV-cache costs about 72 KB per token, which is why a 500k window would need roughly 36 GB of RAM we do not have
Reasoning256 tokens per ordinary question, 512 for hard ones, thinking pass on every non-trivial turn. Answers capped at 220 with a 12-token floor and sentence continuation
TrainingFree Kaggle T4, LoRA r=16, 3 epochs, notebook embeds the corpus. Kernels: NEXUS V1 (preserved), NEXUS V2 (current)
Inside opencodeModel id nexus-v2 ("NEXUS V2 (local)"), same hardening as v1: no tool calls, no attachments, local server only
Evaluationeval/run_battery.py (147 rows), eval/consistency.py --sem (semantics), fabrication sweep, conversation replays. One command each, logged with the full prompt for replay

8. Summary

  • Same idea, harder floor: identity in files, one narrow training pass, offline. v2 adds a runtime that checks its own files, checks the outside world when allowed, and refuses to ship a number it cannot point to.
  • The rule in one line: know it, check it, or say you don't know. Fabrication is never an acceptable answer; hesitation on things it has was trained out after it was measured.
  • Every claim has a run behind it: the battery table, the semantics scoring rules, and the fabrication sweep are in the repository, rerunnable on the free tier.
  • What v2 is for: an instrument whose answers come from files, lookups and weights you can name, so what it communicates can be read as a measurement instead of a reward echo.
